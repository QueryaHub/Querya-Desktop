# ТЗ Блок A: Core Host (Ядро Flutter и SDUI)

## 1. Введение и Зона Ответственности
**Core Host (Блок A)** — это основное приложение Querya Desktop. Оно ничего не знает о внутренней специфике баз данных из плагинов (например, как работает протокол ClickHouse). Его задача — быть "тупым" (в хорошем смысле) рендерером интерфейсов и умным оркестратором процессов.

**Основные задачи:**
1. Жизненный цикл плагинов (Координация с Блоком C).
2. Отрисовка Server-Driven UI (SDUI) на основе JSON.
3. Управление секретами пользователя.

---

## 2. Server-Driven UI (SDUI) Компоненты

Ядро должно предоставлять фабрики виджетов (Widget Factories), которые преобразуют JSON-схемы в реальные компоненты `shadcn_flutter`.

### 2.1. Dynamic Form Builder (`SduiFormBuilder`)
Компонент, получающий JSON-конфигурацию формы и возвращающий `Form` с контроллерами.

**Поддерживаемые типы полей:**
- `text` (TextFormField)
- `number` (TextFormField с валидацией только чисел)
- `password` (TextFormField с обфускацией, `obscureText: true`)
- `checkbox` (Switch/Checkbox для булевых значений)
- `select` (Dropdown для выбора из списка)
- `file_picker` (Поле с кнопкой вызова системного окна выбора файла — для SQLite или SSL-сертификатов)

**Сбор данных:** 
Ядро отвечает за валидацию "Required" полей. После успешной валидации собирается `Map<String, dynamic>` и отправляется через Блок C (RPC) в плагин.

### 2.2. Dynamic Tree Renderer (`SduiTreeBuilder`)
Компонент для рендеринга `SidebarTree` навигации по базам данных.
- Должен поддерживать "ленивую загрузку" (Lazy Loading). Когда узел имеет флаг `expandable: true` и пользователь кликает на него, Flutter должен отправить RPC-запрос `fetchTreeChildren(nodeId)` и динамически добавить детей в дерево после получения ответа.

## 3. Управление Секретами (Security)
Плагины **не имеют права** сохранять пароли или токены на жесткий диск.
1. Все пароли, вводимые в SDUI-формах (поля с типом `password`), сохраняются ядром в `flutter_secure_storage`.
2. В локальную SQLite-базу Querya Desktop сохраняются только настройки хоста, портов и ID подключения.
3. При попытке подключения к БД, ядро достает пароль из безопасного хранилища, склеивает его с конфигурацией и передает в RPC-вызов `db.connect(credentials)`. Пароль существует только в оперативной памяти процесса-плагина.

---

## 4. SQL-редактор и Таблица Результатов
- Плагин возвращает ядру только сырые данные (результаты `SELECT` запросов) в виде стандартизованного JSON: `{"columns": [...], "rows": [...]}`.
- Ядро (Блок A) самостоятельно отрисовывает их в `TableView` с пагинацией.
- Ядро обеспечивает подсветку синтаксиса в редакторе (возможно, запрашивая словарь ключевых слов у плагина).
