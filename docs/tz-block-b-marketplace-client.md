# ТЗ Блок B: Marketplace Client (Менеджер расширений)

## 1. Введение и Зона Ответственности
**Marketplace Client (Блок B)** — подсистема Querya Desktop, ответственная за обнаружение, установку, валидацию и обновление плагинов. Работает аналогично менеджерам пакетов (npm, pub).

**Основные задачи:**
1. Интеграция с REST API Маркетплейса.
2. Безопасное скачивание и проверка `sha256`.
3. Управление локальной директорией `~/.querya/extensions/`.

---

## 2. Структура Директорий и Файловая Система

Все расширения устанавливаются в пользовательскую директорию для обеспечения изоляции от системных файлов.
- **Linux/macOS:** `~/.querya/extensions/`
- **Windows:** `%APPDATA%\Querya\extensions\`

Каждое расширение распаковывается в папку со своим ID (например, `~/.querya/extensions/queryahub.clickhouse-driver/`).
Внутри папки обязательно присутствует `manifest.json`.

---

## 3. Жизненный Цикл Установки Расширения

1. **Запрос к API:** Клиент запрашивает `/api/v1/extensions/queryahub.clickhouse-driver`.
2. **Получение Манифеста:** Бэкенд возвращает метадату, включая URL для скачивания `.zip` и его `sha256` хеш.
3. **Скачивание:** Клиент загружает архив во временную директорию (Temp). В этот момент обновляется UI-стейт `downloadProgress`.
4. **Валидация (КРИТИЧНО):** Клиент вычисляет `sha256` скачанного файла. Если он не совпадает с тем, что отдал API, архив удаляется, а пользователю выдается ошибка `SECURITY_CHECKSUM_MISMATCH`.
5. **Распаковка:** Если проверка пройдена, архив распаковывается в целевую директорию.
6. **Регистрация:** Клиент уведомляет Блок A (Core Host) о появлении нового расширения. Блок A читает манифест и обновляет UI.

---

## 4. Сетевой Слой (API Контракты)

Необходимо реализовать абстракцию `MarketplaceRepository`, чтобы методы можно было легко мокать при тестировании.

```dart
abstract class MarketplaceRepository {
  /// Получить популярные расширения
  Future<List<ExtensionManifest>> getTrending();
  
  /// Поиск по маркету
  Future<List<ExtensionManifest>> search(String query);
  
  /// Скачивание с прогресс-коллбэком
  Future<File> download(String url, {void Function(double)? onProgress});
}
```

---

## 5. Обновления и Версионирование
- При запуске (или раз в сутки) клиент опрашивает API маркета, отправляя список ID установленных расширений и их версии.
- Бэкенд отвечает списком доступных обновлений.
- В UI Маркета на вкладке "Updates" появляется красный бейдж с количеством доступных апдейтов. Установка обновления повторяет цикл установки (заменяя файлы в директории).
